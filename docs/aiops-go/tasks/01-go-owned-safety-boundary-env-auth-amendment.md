## 2. Required authentication boundary

- OpenStack authentication inputs for the Go manual diagnostic process come only from its process environment, provided by a trusted operator-controlled launcher.
- Go must not itself locate/read/load `.env` or use `clouds.yaml`, `secure.yaml`, or another profile as an authentication source or fallback. Do not invoke the root Makefile for credential loading or add a dotenv/auth-profile parser dependency. Any separate trusted noncredential policy/configuration source remains governed by the parent ADR/task; U4 does not authorize changing that source or loading credentials from it.
- Select the Gophercloud v2.14.0 application-credential ID form. The closed authentication-input set is exactly `OS_AUTH_URL`, `OS_APPLICATION_CREDENTIAL_ID`, and `OS_APPLICATION_CREDENTIAL_SECRET`, all required and nonempty. Use Keystone v3 without v2 fallback; scope is implicit in the credential, so do not send any explicit scope. Reject missing, malformed, conflicting, or unsupported inputs before authentication. Use synthetic values only in fixtures; never expose actual credential values.
- Reject application-credential name, username/domain, user-ID, password/passcode, project selectors, deprecated tenant aliases, system-scope and token-input modes. The helper reads additional selectors and does not read `OS_TOKEN`; its request builder gives password/passcode precedence over application credentials. Reject such conflicts before the helper can influence authentication or construct explicit options from the closed set. Tokens issued by authentication are output, not an input mode.
- The environment is not an authorization policy source. Authenticate only as the dedicated `aiops-assistant-project-reader`; retain project label `admin` (not administrator authority), domain `default`, the expected project identity, restricted `reader` role, one-month expiry, and admin-team rotation/revocation. Verify authenticated canonical user and project IDs, and expected identity/domain labels where available, against independent trusted policy before any resource read. Missing/mismatched identity, project, or policy fails closed without a fallback credential. No actual expected user/project IDs or protected endpoint values enter Git, logs, audit or reports.
- Use the separately protected noncredential JSON policy at proposed fixed path `/opt/openstack-ai-ops-assistant/policy/diagnostics.json`: policy directory `root:aiops_assistant` `0750`; regular non-symlink file `root:aiops_assistant` `0640`, runtime-unwritable and not replaceable by the runtime. Validate relevant path components and metadata. A trusted operator/security administrator manages it; use a closed schema and Go standard-library parsing. The environment, credential/profile contents, caller/model and catalog do not supply or override policy. The operator atomically updates policy and may remove or disable access. No further individual endpoint or route risk approval is required within this lab under the owner's decision; this does not authorize changes to identity, project, privilege, routes, infrastructure or installation. Protected current policy still controls destination grants.
- The policy binds independently confirmed expected user/project IDs and approved authentication/service endpoints. Default deny; only operator-approved server IDs are permitted. Project-wide summary requires a distinct grant. Exact-name resolution requires a separate scoped grant; a bounded exact-name search within the fixed project may receive limited metadata for non-allowlisted servers, which must be minimized. Reject ambiguous matches and perform no further read unless the resolved ID is approved. Without that grant, require a UUID and make no name search.
- No 30-day policy-validity limit or corresponding renewal is required for this MVP PRD/story; do not infer another mandatory period. Establish currentness independently of the policy's own claims; revoked or superseded policy must not regain authority through stale copies or rollback, including after restart, and inability to establish currentness fails closed. A trusted administrative version/provenance mechanism is Level 1 within the protected-policy boundary, not a new service or privilege; if no compliant mechanism fits, stop and escalate the specific required change. Revalidate current policy before every credential-bearing operation and related lookup; missing, unsafe, invalid, revoked or incompatibly changed policy, or inability to establish reliable time for required controls, stops further contact without automatic retry or readmission. Enforce any separately applicable authorized validity constraint if present; do not invent a mandatory new policy expiry. An already-sent request cannot be undone; retain truthful audit/cancellation. Credential expiry and rotation remain separate and unchanged. Independently confirmed real values, administrative provenance, a real policy artifact and current deployed policy are not yet evidenced; keep live access disabled until established through the protected operator procedure and applicable live gates. Their absence does not block independent review or separately authorized offline implementation with synthetic policy values and fake/local transports after the required candidate approval/commit and fresh preflight.
- Validate the authentication endpoint against independently trusted approved deployment context before sending credentials; validate each catalog-derived service destination against policy before sending a token or making discovery/resource requests. `OS_REGION_NAME`, `OS_INTERFACE`, proxy variables, CLI cloud/config selectors, request data, or model output cannot choose service endpoints, region, targets, tools, budget, audit path, or approval state. Preserve fixed destination, redirect, proxy, response-size, cancellation, collection and audit controls.
- The documented Keystone HTTP exception covers Go Delivery 1 application-credential authentication over the management path from `assistant02` to `http://192.168.121.5:5000/v3`. The owner, as risk owner, separately accepts service HTTP for all deliveries in this lab until another PRD/story addresses it, with no further individual endpoint or route risk approvals. This amendment implements only Go Delivery 1; independent protected policy still limits destinations. The decision does not authorize route changes, deployment, live use or automatic changes to legacy contracts. Exact service endpoints and route evidence remain independently unverified.
- Neither the Keystone nor service HTTP exception has an expiry for now; the previously asserted `2027-02-07 17:11 UTC` cutoff is not authorized. The owner is responsible for both exceptions. HTTP permits credential/token interception, peer impersonation, and forged identity, catalog or diagnostic responses; fixed policy and origins do not authenticate an HTTP peer. Confidential authenticated TLS is safer. Keep live use disabled pending the separately authorized live acceptance gate.
- Never forward OpenStack variables or secrets to Codex, Pi, another model, or child processes. Do not expose actual credentials or synthetic canaries through argv, logs, errors, tool results, audit, reports, or model input. Add synthetic canary tests for existing Codex/Pi child-environment boundaries.
- The existing revised/Python profile-based contracts continue to apply to those runtimes and are not changed by this Go-only amendment.
